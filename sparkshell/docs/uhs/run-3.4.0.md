# SparkShell 3.4.0 的 UHES 运行记录

UHES（范式演化设计师 Agent，概念架构）落到本仓，只保留能产生决定的部分：
**需求 DNA → 范式匹配 → 方法论 → 蓝图 → 八维验证 → 交叉验证 → 孵化 → 矩阵登记**。
每一步都写"因为什么、放弃了什么"，不写激励性废话。

## S1 需求 DNA（从用户原话里抽，不转述）

| 基因 | 原话/事实 | 对 3.4.0 的约束 |
|---|---|---|
| 交办式 | 「一句话交给 ai」「傻瓜式操作」 | 不新增术语、不新增必填项 |
| 全功能 | 「不要省略」「2–3 百 M 不算大」 | 双包（Alpine 62 M / Debian 179 M）继续并行，不为瘦身砍能力 |
| 真能用 | 「不能推送以后我安装不了或者不能用」 | 每个版本必须有可下载链接 + sha256 + CI 绿 |
| 反脆弱 | 「重试几次」「不要换模型」 | 接入点失败只重试，不静默换模型 |
| 图纸优先 | 「照着图纸看」 | 每条改动尽量对应 dsh-go 逆向库里的证据 |
| 少打扰 | 「测试连接点了没反应」这类反馈 | 交互必须有即时反馈；反过来，不该问的别问 |

关键 DNA 冲突：**审批**。harness 需要审批（安全），但用户要"一句话交办"（低摩擦）。
解法不是二选一，而是**按危险度分流**——这就是 3.4.0 的主线。

## S2 范式匹配

| 候选范式 | 判定 |
|---|---|
| 全自动 agent（无审批） | 否。rm -rf 一次就够毁掉信任 |
| 每步审批 | 否。用户会点「全部允许」，等于没有审批 |
| **风险分级审批** ＋ **能力分档（模型/视觉得分开选）** | 采用。摩擦只出现在真危险处 |

## S3 方法论

- **危险度分级**：把"不可逆"当唯一判据，而不是"是否写文件"。删 `/root/build` 可逆（容器内、可重建），删 `/` 不可逆。
- **单一真值**：模型选择走 `ApiConfig.modelFor()`，UI 不各自判断。
- **可测的纯函数**：`approvalFor()`、`modelFor()` 都是纯函数，单测覆盖正反例，不靠界面点。
- **反证优先**：每条规则先写"什么命令必须不被拦"，再写"什么必须被拦"——防止规则越写越像形式主义。

## S4 蓝图（3.4.0 实际改动）

1. `lib/agent/approval.dart`（新，3.1 KB）
   - 22 条危险规则；`write_file/edit_file/apply_patch` 写容器外才拦；`ssh_exec` 一律拦。
   - 返回 `ApprovalRequest(reason, snippet)`，弹窗标题直接说人话（"要格式化分区"）。
2. `chat_page._approve`：`approvalFor() == null` 直接放行，不再每个工具弹窗。
3. `ApiConfig.visionModel` + `modelFor({hasImages})`：带图且配了看图模型才切；纯文字仍走主模型。
4. 设置页新增"看图模型（可选）"；`LlmClient`/`AgentRunner` 增加 `modelOverride`，只在一个地方决定模型。
5. 测试：`test/approval_test.dart`（13 条必拦 + 7 条必放 + 3 条路径 + 截断）、`test/model_slot_test.dart`（4 条选择 + 落盘兼容）。

## S5 八维验证

| 维度 | 结论 |
|---|---|
| 正确性 | 22 条规则正反例各测；`modelFor` 四态（无图/有图/未配/空白） |
| 安全性 | 拦的是不可逆动作；放行的是可逆动作。误拦代价 = 多一次点击；漏拦代价 = 数据没了 |
| 兼容性 | 老配置文件缺 `visionModel` 读成空串，不崩 |
| 性能 | 规则是预编译正则 + 线性扫描，单次 < 1 ms |
| 可维护 | 规则集中在一张表，加规则不改逻辑 |
| 可观测 | 弹窗标题即原因，用户知道为什么被拦 |
| 可回滚 | 三个文件独立，回退不影响会话/容器 |
| 体验 | 从"每个工具都问"降到"只有危险才问" |

## S6 交叉验证（对 dsh-go 逆向库）

- dsh-go 有 `phone_approval`（Dart 侧审批）与 `PhoneA11yService`，说明**审批是同类产品的必备件**，不是我们多事。
- 但它把审批放在 phone 通道（本机执行）；我们放在 agent 循环入口，覆盖 bash/写文件/ssh，范围更大。
- 它 `libproot.so` 不动字节、走 `PROOT_LOADER`（3.3.1 已对齐）。
- 差异保留：它做设备控制（root/Shizuku/ADB），我们不做——那会引入不可控权限面，与"装得上、用得稳"冲突。

## S7 孵化（交付）

- `3.4.0+38`，CI 内 `flutter analyze` + `flutter test` 作为门禁；沙箱无 Flutter，本地不做假验证。
- 发布走 release → VPS `/opt/dl` → CF 隧道，`latest.json` 同步。

## 被否掉的三件事（同样重要）

1. **工具调用合并成一张卡**：视觉上更干净，但会让"正在跑哪一步"消失，长任务里用户不知道卡在哪。留到有折叠态设计再做。
2. **自动切换视觉模型到主模型**：免费接入点大多不支持图片，自动切过去只会换来 400。必须用户显式填。
3. **为降体积砍 Debian 包**：用户明确要全功能，体积换能力这笔账他算过。
